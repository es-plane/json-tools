Format & Validate JSON Without Leaking Secrets

You will learn: tell "ugly" from "invalid", format safe dumps in your browser, validate with jq locally, and route by size and secret. Not for: jq daily users, schema design.

0. The one rule (30 sec)

Ask "where did my bytes go?" before pasting. Client-side = stays in your browser. Server-side = leaves to someone's server. Secrets never leave your machine.

1. Ugly vs invalid (3 min)

Ugly but valid: {"id":1,"tags":["a","b"],"ok":true} — just needs indent. Invalid: {"a":1,} (trailing comma) or {'a':1} (single quotes). Formatting cannot fix invalid JSON. Validate first, fix the char, then format.

Try now on the free formatter (100% client-side): paste each, read the error position.

2. Format the safe dump (4 min)

Exercise E1: paste {"id":1,"tags":["a","b"],"ok":true} → Format → 2-space indent. Done when it parses with no error.

3. Your first jq (5 min)

Exercise E5: in a terminal, save a file data.json, then run:

jq empty data.json && echo OK
jq . data.json > data.pretty.json

No jq? Rescue ladder: python3 -m json.tool data.json > out.json. Same job, no install.

4. Route by size and secret (3 min)

Exercise E4: a 200KB API dump containing "token":"REDACTED".

  • Small + safe (<1MB, no secrets): browser formatter is fine.
  • Large OR secret: local CLI only — jq . dump.json. Never upload.

Done when: you validate one real file locally and can say where the bytes went.

Fix the top 3 errors

  • Unexpected token } — trailing comma. Delete it.
  • Unexpected token ' — single quotes. Use double quotes.
  • Unexpected end — truncated paste. Re-copy the full response.
